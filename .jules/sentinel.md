## 2024-05-18 - [Fix DoS vulnerability in HTML colspan parsing]
**Vulnerability:** Uncontrolled resource consumption leading to Denial of Service (DoS) in HTML table extraction. The HTML parser blindly trusted the `colspan` attribute from user-provided MHTML files and expanded columns accordingly in a loop.
**Learning:** We must not blindly trust size-related attributes like `colspan` or `rowspan` parsed from untrusted HTML/MHTML sources. An attacker could specify artificially large sizes, forcing unbounded loops and enormous memory allocation, crashing the ETL gateway pipeline.
**Prevention:** Bound looping constructs driven by user input. In this case, `colspan` has been bounded to `100000`, failing closed aggressively and returning a `TableExtractError` when the limit is exceeded.
## 2024-05-24 - Prevent SQL Injection with array parameterization
**Vulnerability:** A Bandit security scan identified a medium-severity issue (B608:hardcoded_sql_expressions) in `postgres_loader.py` caused by using an f-string to construct an `IN ({placeholders})` clause dynamically.
**Learning:** While the inputs were dynamically generated and partially controlled by the application logic, directly interpolating query strings creates a theoretical and potentially actual SQL injection vector. `psycopg3` natively supports array parameterization with `ANY(%s)`. When parameterizing `ANY(%s)` queries, `psycopg3` adapts Python lists (e.g., `(list(my_items),)`) into PostgreSQL arrays, rather than tuples.
**Prevention:** Avoid f-strings for SQL query formulation, particularly with `IN` clauses. Instead, utilize `psycopg3`'s native array parameterization (`= ANY(%s)`) passing a Python list wrapper to securely construct queries with dynamic input collections.
