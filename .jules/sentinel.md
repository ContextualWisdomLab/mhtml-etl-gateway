## 2024-05-18 - [Fix DoS vulnerability in HTML colspan parsing]
**Vulnerability:** Uncontrolled resource consumption leading to Denial of Service (DoS) in HTML table extraction. The HTML parser blindly trusted the `colspan` attribute from user-provided MHTML files and expanded columns accordingly in a loop.
**Learning:** We must not blindly trust size-related attributes like `colspan` or `rowspan` parsed from untrusted HTML/MHTML sources. An attacker could specify artificially large sizes, forcing unbounded loops and enormous memory allocation, crashing the ETL gateway pipeline.
**Prevention:** Bound looping constructs driven by user input. In this case, `colspan` has been bounded to `100000`, failing closed aggressively and returning a `TableExtractError` when the limit is exceeded.
## 2026-09-01 - SQL Injection Vector in Legacy Table Name Checks
**Vulnerability:** A string-interpolated query was constructing an `IN ({placeholders})` clause inside `_reject_legacy_table_split` in `src/mhtml_etl_gateway/postgres_loader.py` to check for legacy tables. While the table names are generated via a python schema class, any usage of string formatting inside query strings is an injection risk and is flagged by static analyzers like Bandit (B608).
**Learning:** `psycopg` (v3+) supports PostgreSQL array parameterization directly via `ANY(%s)`. Standard parameterization in Python cannot be directly applied to a tuple of parameters to populate an `IN` clause cleanly without string construction.
**Prevention:** Always use `ANY(%s)` combined with passing the values as a list `(list(values),)` in `psycopg` to safely and natively bind arrays, rather than formatting placeholders into an `IN` clause.
