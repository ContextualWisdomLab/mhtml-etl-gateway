## 2024-05-18 - [Fix DoS vulnerability in HTML colspan parsing]
**Vulnerability:** Uncontrolled resource consumption leading to Denial of Service (DoS) in HTML table extraction. The HTML parser blindly trusted the `colspan` attribute from user-provided MHTML files and expanded columns accordingly in a loop.
**Learning:** We must not blindly trust size-related attributes like `colspan` or `rowspan` parsed from untrusted HTML/MHTML sources. An attacker could specify artificially large sizes, forcing unbounded loops and enormous memory allocation, crashing the ETL gateway pipeline.
**Prevention:** Bound looping constructs driven by user input. In this case, `colspan` has been bounded to `100000`, failing closed aggressively and returning a `TableExtractError` when the limit is exceeded.
## 2026-09-03 - Fix SQL Injection Vector in Legacy Table Split Validation
**Vulnerability:** A medium severity `[B608:hardcoded_sql_expressions]` SQL injection vector was identified by `bandit` in `src/mhtml_etl_gateway/postgres_loader.py`. The `IN` clause of a database query was constructed using a Python f-string `IN ({placeholders})` combined with manually injected placeholder marks for parametrized values.
**Learning:** Using f-strings to construct SQL queries, even just for formatting placeholders, bypasses static security analysis checks, throws warnings (Bandit B608), and increases the risk of injection if the number of placeholders or parameter unpacking logic changes or is mismanaged.
**Prevention:** In psycopg3+, always parameterize array lookups natively using PostgreSQL's `ANY(%s)` syntax and pass the parameter as a wrapped Python list `(list(values),)`. This allows the driver to handle dynamic sized arrays securely without manual placeholder formatting.
