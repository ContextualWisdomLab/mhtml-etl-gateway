## 2024-05-18 - [Fix DoS vulnerability in HTML colspan parsing]
**Vulnerability:** Uncontrolled resource consumption leading to Denial of Service (DoS) in HTML table extraction. The HTML parser blindly trusted the `colspan` attribute from user-provided MHTML files and expanded columns accordingly in a loop.
**Learning:** We must not blindly trust size-related attributes like `colspan` or `rowspan` parsed from untrusted HTML/MHTML sources. An attacker could specify artificially large sizes, forcing unbounded loops and enormous memory allocation, crashing the ETL gateway pipeline.
**Prevention:** Bound looping constructs driven by user input. In this case, `colspan` has been bounded to `100000`, failing closed aggressively and returning a `TableExtractError` when the limit is exceeded.
## 2024-05-18 - [Fix Bandit B608 static analysis warning on f-string IN queries]
 **Vulnerability:** Constructing SQL `IN` clauses with f-strings or string formatters triggers Bandit static analysis warnings (B608) as a potential SQL injection vector. While the previous implementation safely interpolated only `%s` placeholders and was not exploitable, dynamic SQL query generation via f-strings is a maintainability risk and violates static analysis contracts.
**Learning:** Security linters (SAST) often flag string interpolation used to build SQL query structures because it creates a potential attack surface if developer discipline slips and user input is ever accidentally included in the interpolation string.
**Prevention:** Avoid dynamic query construction using python string manipulators. Always use native database array passing, such as PostgreSQL's `ANY(%s)` array match operator, allowing the database driver (`psycopg`) to safely serialize and handle lists parametrically.
