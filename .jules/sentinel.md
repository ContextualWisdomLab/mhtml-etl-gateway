## 2024-05-18 - [Fix DoS vulnerability in HTML colspan parsing]
**Vulnerability:** Uncontrolled resource consumption leading to Denial of Service (DoS) in HTML table extraction. The HTML parser blindly trusted the `colspan` attribute from user-provided MHTML files and expanded columns accordingly in a loop.
**Learning:** We must not blindly trust size-related attributes like `colspan` or `rowspan` parsed from untrusted HTML/MHTML sources. An attacker could specify artificially large sizes, forcing unbounded loops and enormous memory allocation, crashing the ETL gateway pipeline.
**Prevention:** Bound looping constructs driven by user input. In this case, `colspan` has been bounded to `100000`, failing closed aggressively and returning a `TableExtractError` when the limit is exceeded.

## 2024-10-24 - [Fix SQL Injection Vector in table legacy checks]
**Vulnerability:** Possible SQL injection vector through string-based query construction when finding legacy table candidates in `postgres_loader.py`. Although the original code parameterized correctly for an `IN` clause with a tuple by unpacking placeholders `IN (%s, %s)`, this triggers static analysis (Bandit B608) false-positives and is slightly harder to reason about due to dynamic formatting of the string itself.
**Learning:** Using Python f-strings to inject placeholders like `f"IN ({placeholders})"` sets off static security scanners, and creates unnecessary complexity as the list grows. Psycopg (v3+) supports PostgreSQL array parameterization directly natively.
**Prevention:** Always use PostgreSQL's `ANY(%s)` operator and pass a single Python list of arguments rather than unpacking multiple `%s` parameters for an `IN` clause. This removes all dynamic string formatting from the query string, resolving static scanner warnings and reducing error-prone string manipulation.
