## 2024-05-18 - [Fix DoS vulnerability in HTML colspan parsing]
**Vulnerability:** Uncontrolled resource consumption leading to Denial of Service (DoS) in HTML table extraction. The HTML parser blindly trusted the `colspan` attribute from user-provided MHTML files and expanded columns accordingly in a loop.
**Learning:** We must not blindly trust size-related attributes like `colspan` or `rowspan` parsed from untrusted HTML/MHTML sources. An attacker could specify artificially large sizes, forcing unbounded loops and enormous memory allocation, crashing the ETL gateway pipeline.
**Prevention:** Bound looping constructs driven by user input. In this case, `colspan` has been bounded to `100000`, failing closed aggressively and returning a `TableExtractError` when the limit is exceeded.
## 2026-10-01 - Avoid f-strings for SQL query parameterization
**Vulnerability:** A Bandit medium severity warning (`B608:hardcoded_sql_expressions`) was found when an `IN ({placeholders})` clause was constructed using string interpolation (`f-string`) for a dynamic list of table names in `src/mhtml_etl_gateway/postgres_loader.py`.
**Learning:** Using `f-strings` to generate dynamic `IN` clauses with placeholders (even if the values mapped to those placeholders are passed securely later) triggers static security scanners because it resembles insecure string concatenation. Instead, psycopg3`s native `ANY(%s)` array parameterization is fully secure and doesn`t trigger the scanner.
**Prevention:** For dynamic `IN` conditions in SQL, always use `col = ANY(%s)` and pass a Python `list` via parameters rather than generating `IN (%s, %s...)` strings dynamically.
